# Web UI (all screens)

Scope: the Automatic Media Archive LAN web UI. Mode: Operate. Users: owner + household, on phone at the drive and on desktop for Review. Job: see what the drive and pipeline are doing, and resolve Review items with one clear question each. Mockups in `docs/mockups/` are acceptance criteria for tickets #1, #2, #4, #5, #7, #8, #12, #13, #14, #16.

## Direction contract

THESIS: The pipeline is a record-shop browser bin: every Disc stands behind its stage divider, its status the single sticker on its corner. Refuses the default sidebar + equal cards + status-badge table.

OWN-WORLD: Cool grey bin ground, near-white sheets, near-black ink; four divider colours own stages (Ripping cobalt, Needs Review tomato, Encoding mustard, Filed teal). Die-cut divider tabs with an asymmetric cut, one price-gun sticker per Disc, 1px hairline grid, one rule weight, three ink values. Archivo / Archivo Narrow.

STORY: In one glance the visitor knows what is in the drive, whether anything needs them, and what to do next; Review asks one question and files the Disc.

FIRST VIEWPORT: Top bar (name, Now / Review·count / Archive / Settings, scratch meter). Left 780px: the Disc in the drive at the largest scale with progress, then the Needs Review bin with action buttons. Right: Ripping, Encoding, Filed today bins stacked small. Primary action = first Review button.

FORM: Browser Bin, position 3 on my ordered list; seed:fd7fe342daf2a00b. Signature move: stage divider tabs; a Disc changing stage moves behind the next divider. Raises: hairline grid (annual), one rule weight + state as marks (rail), whole-cell thumbnails (doujin), size ranks urgency (atlas).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
